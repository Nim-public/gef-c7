# Cross-Modal Validation — Automated Integrity Checks

**What you'll learn:** the checks that run before embeddings are built:
referential integrity, duration agreement, coverage, and a validation report
format your CI can gate on.

## 1. The check catalog

| # | Check | Catches | Severity |
|---|---|---|---|
| V1 | every `rel_path` exists, hash matches | moved/edited files after manifest build | error |
| V2 | manifest row count == embedding matrix rows | row misalignment | error |
| V3 | image aspect ratio within 1% of EXIF-transposed dims | sideways images | warning |
| V4 | audio duration ≈ container duration ±0.5 s | codec/decode mismatch | error |
| V5 | sampled-frame count == settings `frames` | partial ingest | error |
| V6 | subtitle span ⊆ audio span (± drift) | offset bugs | warning |
| V7 | every unit has license in allow-list | permissions leak | error |
| V8 | OCR/ASR text present for units flagged `sidecar` | missing text modality | warning |

Severity matters: **errors block the pipeline; warnings land in the report
with owners.** A pipeline that fails on warnings trains you to ignore it.

## 2. Implementation as a pure function over the manifest

```python
from pathlib import Path
import hashlib, pandas as pd, numpy as np

def sha256_file(p: Path, chunk: int = 1 << 20) -> str:
    h = hashlib.sha256()
    with p.open("rb") as f:
        while b := f.read(chunk):
            h.update(b)
    return h.hexdigest()

def validate(manifest: pd.DataFrame, embeddings: np.ndarray | None,
             frames_root: Path, settings: dict) -> pd.DataFrame:
    rows = []
    def add(check, unit_id, severity, detail):
        rows.append({"check": check, "unit_id": unit_id,
                     "severity": severity, "detail": detail})

    for r in manifest.itertuples():
        p = Path(r.rel_path)
        if not p.exists():
            add("V1", r.unit_id, "error", "missing file"); continue
        if sha256_file(p) != r.sha256:
            add("V1", r.unit_id, "error", "hash mismatch")
        if r.modality == "video":
            n = len(list((frames_root / r.unit_id).glob("f*.jpg")))
            if n != settings["video"]["frames"]:
                add("V5", r.unit_id, "error", f"{n} frames")
    if embeddings is not None and len(manifest) != embeddings.shape[0]:
        add("V2", "*", "error",
            f"manifest {len(manifest)} vs matrix {embeddings.shape[0]}")
    return pd.DataFrame(rows)
```

Note the shape: **pure function in, report DataFrame out.** No prints, no
`exit()` — the caller (CLI or CI) decides what severity means.

## 3. The report artifact (and how CI gates on it)

`reports/validation-report.md`, generated by one command:

```text
# Validation report — corpus-manifest v3 — 2026-09-05T17:31Z

| check | severity | count | first 3 units |
|---|---|---|---|
| V1 hash | error | 2 | img_042, img_118, … |
| V5 frames | error | 1 | vid_007 |
| V6 subs | warning | 4 | vid_003, vid_009, … |

Gate: FAIL (3 errors). Warnings: 4 (owner: alignment, due: week 8).
```

```python
def gate(report: pd.DataFrame) -> int:
    errs = (report.severity == "error").sum()
    return 1 if errs else 0          # CI exit code

# py scripts/validate_corpus.py && git commit   ← errors block the chain
```

## 4. The two checks everyone skips (and regret)

**V2 (row alignment)** is one line and catches the single most expensive
failure in multimodal RAG: a manifest re-sorted after the matrix was built.
Every retrieved "document" then belongs to another vector — retrieval
quality collapses *randomly*, which looks like a model problem and is an
off-by-one join. If you implement one check, it is V2.

**V8 (sidecar presence)** encodes the modality-gap lesson from
[`../01-multimodal-ai-landscape/04-the-modality-gap.md`](../01-multimodal-ai-landscape/04-the-modality-gap.md):
every unit whose inventory row promises OCR/ASR text must have it *before*
indexing, or the gap silently persists. As a warning it becomes a work item;
as an error it would block corpora where sidecars arrive in Week 08.

## 5. When validation runs

| Trigger | Checks | Cost |
|---|---|---|
| After ingest (per batch) | V1, V4, V5, V7 | full, on the batch |
| Before indexing | V2, V5, V7, V8 | metadata only, seconds |
| CI (every push) | V2 + a 5-unit sample of V1 | seconds |
| Before publishing the repo | V7 + exclusions parity | metadata only |

The pattern: cheap checks constantly, expensive checks at boundaries. Full
hash verification (V1) on every CI run would dominate your build time for
zero added safety between pushes.

## Pitfalls

- Validating against `data/processed/` instead of `data/raw/` — you would catch cache issues but miss source edits.
- Reports without timestamps and manifest version — unreproducible; the header line is not decoration.
- Warnings without owners — they rot; every warning row gets a "due" week.
